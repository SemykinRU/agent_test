# agent_test
Сервис-реестр HTTP-клиентов нескольких поставщиков

1. Запусти приложение.
2. Выполни POST-запрос на http://localhost:8090/api/auth/login с телом {"username": "user", "password": "password"}.
3. Получи JWT-токен в ответе.
4. Выполни запрос к любому защищенному эндпоинту с заголовком Authorization: Bearer <ваш_токен>
http://localhost:8090/update POST-запрос, в теле принимает список поставщиков [{"id": 1, "baseUrl": "http://test.ru", "apiKey": "sdjahfgjedfnkjo"}, {"id": 1, "baseUrl": "http://test.ru", "apiKey": "sdjahfgjedfnkjo"}]
http://localhost:8090/upload POST-запрос для загрузке файла, файл указывать в параметрах как file <img width="971" height="63" alt="image" src="https://github.com/user-attachments/assets/ae17e683-6f23-41fe-a6d5-42ac1acff225" />
http://localhost:8090/suppliers?id={id}&phone={phone} GET-запрос из ТЗ "По идентификатору поставщика и номеру телефона сервис узнаёт, доступен ли номер телефона"



Постановка:
Разработать сервис-реестр HTTP-клиентов нескольких поставщиков. У поставщика есть идентификатор, базовый URL и API-ключ. Набор поставщиков можно заменить целиком. По идентификатору поставщика и номеру телефона сервис узнаёт, доступен ли номер телефона.
Запрос к поставщику: GET {baseUrl}/subscribers/{phone}.
Ответ 200 с телом {"status":"ok"} означает, что номер доступен. 404 означает, что номер недоступен. Остальные HTTP-ошибки и сетевые ошибки доходят до вызывающего кода.
Поставщиков нужно уметь передать готовым списком и реализовать чтением из json-файла на диске.
Java 17, JUnit 5, Spring. Сетевой вызов в тестах подменяется, реального HTTP запроса нет. Покрыть тестами успешный ответ и 404.
Веб-приложение, OAuth, повторные попытки и база не нужны.

Проблемы:
1. lost_update - при параллельном обновлении списка поставщиков.
2. Легко словить OOM, так как все поставщики хранятся в памяти.
